# Risk Register & Mitigasi — DPP Recruitment Portal Dashboard

Dokumen ini memelihara daftar risiko teknis, keamanan, kepatuhan UU PDP, dan infrastruktur beserta status dan rencana mitigasinya.

**Skala Tingkat Risiko:** 🔴 Kritis | 🟠 Tinggi | 🟡 Sedang | 🟢 Rendah

---

## 1. Risiko Keamanan Aplikasi (Application Security)

| ID | Kategori | Deskripsi Risiko & Bukti di Codebase | Dampak | Tingkat | Rencana Mitigasi | Target Fase | Status |
|---|---|---|---|---|---|---|---|
| **R-01** | Auth / Privilege Escalation | Endpoint `GET/POST /api/users` dan `PUT/DELETE /api/users/[id]` tidak memvalidasi session dan role `ADMIN` (`getServerSession()` dipanggil tanpa `authOptions` dan hasilnya tidak dicek). Siapa pun dapat membuat akun `ADMIN` atau mereset password user lain. | Pengambilalihan penuh sistem (*full system takeover*). | 🔴 Kritis | Menambahkan guard `requireRole(['ADMIN'])` menggunakan `getServerSession(authOptions)` di seluruh method `/api/users` dan `/api/users/[id]`, plus proteksi agar admin tidak menghapus dirinya sendiri. | Fase 2 | Open |
| **R-02** | Broken Access Control | Server Actions di `app/actions/master-data.ts`, `dashboard.ts`, `upload.ts`, dan sebagian `job.ts` belum memverifikasi session/role pemanggil. Di Next.js App Router, setiap fungsi `"use server"` adalah HTTP POST endpoint publik. | Pihak tanpa otorisasi dapat memodifikasi master data, job opening, atau membaca metrik internal. | 🔴 Kritis | Membuat helper `requireStaffSession()` di `lib/auth-guard.ts` dan memasangnya di seluruh fungsi Server Actions internal. | Fase 2 | Open |
| **R-03** | Insecure File Upload & Data Loss | `app/actions/upload.ts` menulis file ke `public/uploads/` (dapat diakses publik tanpa login, tanpa validasi *magic bytes*, dan file akan hilang setiap kali container di-rebuild). | Kebocoran dokumen, risiko Stored XSS, dan hilangnya file saat redeploy Docker. | 🔴 Kritis | Mengalihkan seluruh upload dokumen ke Cloudflare R2 via *presigned URL*, memvalidasi tipe file (PDF/JPG/PNG) & ukuran ($\le 5\text{ MB}$), serta menonaktifkan penyimpanan dokumen kandidat ke `public/uploads/`. | Fase 2–3 | Open |
| **R-04** | IDOR pada Dokumen | `GET /api/file?key=...` hanya memeriksa apakah user login, tanpa memeriksa apakah user tersebut adalah staf internal atau pemilik sah dokumen. Kandidat A dapat mengunduh KTP/CV Kandidat B jika mengetahui/menebak `key`. | Kebocoran data pribadi (PII) antar kandidat. | 🔴 Kritis | Memeriksa role (`ADMIN`/`RECRUITER`) atau mencocokkan prefix/record `CandidateDocument.candidateProfile.userId === session.user.id` sebelum men-generate *presigned download URL*. | Fase 2 | Open |
| **R-05** | Hardcoded Default Secrets | `lib/s3.ts` memiliki fallback `"minioadmin"`, `docker-compose.yml` memakai `postgres123` dan `mc anonymous set public`, serta `seed-essential.ts` membuat admin dengan password `"password"`. | Akses tidak sah ke database, object storage, atau akun Super Admin jika lupa diganti saat deploy. | 🟠 Tinggi | Menghapus fallback kredensial di kode produksi (wajib baca dari env), menghapus set public bucket, dan mewajibkan `SEED_ADMIN_PASSWORD` dari variabel environment saat seeding. | Fase 2 | Open |
| **R-06** | Autentikasi Tanpa MFA & Brute Force | Sesuai keputusan bisnis saat ini, login menggunakan Email+Password tanpa MFA. Selain itu `allowDangerousEmailAccountLinking: true` aktif di Google Provider dan panjang password registrasi hanya $\ge 6$ karakter. | Akun staf rentan terhadap tebakan password (*brute-force* / *credential stuffing*). | 🟠 Tinggi | *Accepted Risk (Tanpa MFA)* dengan kontrol kompensasi: wajib password $\ge 8$ karakter kompleks, rate-limiting login (maks 5 gagal / 15 menit), menonaktifkan Google OAuth / `allowDangerousEmailAccountLinking` untuk staf jika tidak dipakai, dan mencatat login gagal di Audit Log. | Fase 2 | Accepted w/ Mitigation |
| **R-07** | Permukaan Serangan Portal Publik | Portal Kandidat (`/candidate/*`, `/api/auth/register`) dan lowongan publik (`/jobs/*`) sudah ada di codebase padahal fokus rilis awal adalah operasional internal. | Pendaftaran akun spam/bot dari internet sebelum sistem siap. | 🟠 Tinggi | Memasang *Feature Flag* (`FEATURE_CANDIDATE_PORTAL=false`, `FEATURE_PUBLIC_JOBS=false`) di Staging & Production; tetap `true` di lokal untuk development. | Fase 2 | Open |
| **R-08** | Kerentanan Dependency (`xlsx`) | Paket `xlsx` `0.18.5` di `package.json` memiliki advisori keamanan publik (Prototype Pollution / ReDoS) saat mem-parsing file eksternal. | Potensi *Denial of Service* saat memproses file Excel berbahaya. | 🟡 Sedang | Menggunakan `exceljs` (yang sudah terinstal di `package.json` versi `4.4.0`) untuk seluruh fitur baca/tulis Excel baru dan membatasi akses fitur import hanya untuk staf internal terautentikasi. | Fase 4–5 | Open |

## 2. Risiko Kepatuhan Data Pribadi (UU PDP No. 27 Tahun 2022)

| ID | Kategori | Deskripsi Risiko | Dampak | Tingkat | Rencana Mitigasi | Target Fase | Status |
|---|---|---|---|---|---|---|---|
| **R-09** | Akuntabilitas & Jejak Audit | Belum ada tabel dan mekanisme `AuditLog` untuk melacak siapa yang mengakses/mengubah data kandidat, dokumen, blacklist, dan user. | Tidak memenuhi kewajiban akuntabilitas pengendali data menurut UU PDP. | 🟠 Tinggi | Menambahkan model `AuditLog` dan mencatat seluruh aksi sensitif (login, manajemen user, perubahan tahap/blacklist, unduh dokumen). | Fase 2–3 | Open |
| **R-10** | Penyimpanan PII (NIK & Dokumen) & Lokasi R2 | `CandidateProfile.nik` disimpan plaintext dan dokumen disimpan di Cloudflare R2 (layanan cloud pihak ketiga). | Risiko eksposur NIK jika DB bocor & kepatuhan transfer data lintas batas (Pasal 56 UU PDP). | 🟡 Sedang | 1) Mengonfigurasi bucket Cloudflare R2 dengan *Location Hint: Asia-Pacific (APAC)* dan enkripsi at-rest bawaan AES-256 под akun resmi DPP.<br>2) Memastikan persetujuan (*Privacy Notice & Consent*) tampil jelas.<br>3) Menyiapkan fitur hapus/anonimisasi data kandidat sesuai permintaan/kebijakan retensi. | Fase 3–5 | Open |

## 3. Risiko Infrastruktur, Deployment & Operasional

| ID | Kategori | Deskripsi Risiko | Dampak | Tingkat | Rencana Mitigasi | Target Fase | Status |
|---|---|---|---|---|---|---|---|
| **R-11** | Kegagalan Build Docker (`standalone`) | `Dockerfile` menyalin `/app/.next/standalone`, tetapi `next.config.ts` belum mengatur `output: "standalone"`. Selain itu `docker-compose.yml` belum memiliki service `app`. | Perintah `docker compose up -d --build` akan gagal membangun image aplikasi. | 🟠 Tinggi | Menambahkan `output: "standalone"` di `next.config.ts`, membuat `.dockerignore`, dan menyusun `docker-compose.prod.yml` / penyempurnaan `docker-compose.yml` dengan service `app`. | Fase 2 | Open |
| **R-12** | Perebutan Resource di VM Non-Odoo (Shared VM) | VM non-Odoo juga menjalankan proyek web & mobile penting lainnya, sementara tahap awal masih menggunakan `docker compose up -d --build` langsung di VM. Proses `next build` dan TypeScript check dapat memakan 100% CPU dan >2 GB RAM. | Aplikasi web/mobile lain di VM yang sama melambat atau terkena *Out-Of-Memory (OOM) kill* saat proses build berjalan. | 🟠 Tinggi | 1) Menjalankan inspeksi kapasitas VM (*read-only*) sebelum deploy.<br>2) Memastikan swap aktif di VM.<br>3) Membatasi CPU/RAM build & runtime di Docker Compose.<br>4) Segera beralih ke build via GitHub Actions + GHCR setelah development selesai 100% (ADR-006). | Fase 2 & 6 | Open |
| **R-13** | Eksposur Port Database ke Publik | `docker-compose.yml` saat ini memetakan `ports: - "5433:5432"` ke `0.0.0.0`. Jika firewall VM tidak memblokir port 5433, database dapat diserang dari internet. | Kebocoran atau perusakan seluruh database rekrutmen. | 🔴 Kritis | Di Staging & Production, menghapus eksposur port publik database atau mem-bind hanya ke `127.0.0.1:5433` di dalam jaringan internal Docker. | Fase 2 & 6 | Open |
| **R-14** | Kepemilikan Repo & Kredensial Pribadi | Repository saat ini masih berada di akun GitHub pribadi developer (`fahruulc`) dan konfigurasi R2 belum terdokumentasi di bawah akun organisasi DPP. | Risiko kehilangan akses kode/storage (*bus factor* = 1). | 🟡 Sedang | Menjalankan sesi *Knowledge Transfer* (KT) minggu ini menggunakan daftar pertanyaan terstruktur, menjaga salinan clone lengkap di lingkungan IT Leader, dan mentransfer repo ke `https://github.com/IT-DPP` saat development selesai 100%. | Fase 1–6 | Open |
| **R-15** | Kompatibilitas Next.js 16 | Proyek memakai Next.js `16.2.12` dan React `19.2.4` yang memiliki perubahan konvensi dibanding Next.js 14/15. | Error runtime/build jika menulis kode dengan pola lama. | 🟡 Sedang | Membaca dokumentasi resmi di `node_modules/next/dist/docs/` sebelum memodifikasi kode pada Fase 2 dan seterusnya (sesuai aturan `AGENTS.md`). | Fase 2+ | Open |
